【一】被改掉的东西是什么

  改之前：被合规复核拦下 / 诉求没说清 / 审批被驳回的案子，界面给一句
          「已转交专人跟进」。这句话在动作上是空的 —— 人看不到在哪动手、
          做了什么、做到哪一步。**把状态当成了功能。**

  改之后：右栏出现「人工跟进」台账（只在需要人接的案子上出现），
          结果卡横幅有「去跟进」、队列条目带状态标签、首屏工作台多一块「等你接手」。
          能做的六件事：接手署名 / 记一条 / 等客户补充 / 转交二线 / 核实结单 /
          **按补充事实重新处置（真的重跑一遍链路）**。

  ▸ 这里修掉的是**这一轮自己发现的第二个断头路**：
    台账把原案还原了，但「按补充事实重新处置」产出的那条结果没还原 ——
    等于人重开页面后看不到自己跟出来的结论。修法：`rerun` 时把新结果的瘦身快照
    也随台账一起存（`run_case`），刷新时按同一 key 还原；重新处置的会话 id 用
    稳定值 `frun-<case_key>`，天然幂等（同一案子只留最近一次结果，不会越刷新越多）。
  ▸ 修之前实测：刷新后队列 1 条（只剩原案）；修之后：2 条，两条都在。

【五】边界：补上事实**不是**万能钥匙（这条同样重要）

  人工写进去的是**事实**，判断仍然归引擎与授权闸。补了事实也未必改变结论：

  · M07（退款金额超实付）
       原判          已拦截
       补事实         「500 系口误，实付 268」（重跑）
       重跑后         **已拦截** / 横幅「已拦截，未执行任何处置」

  · M02（未收到货 · 物流已签收）
       原判          已拦截
       补事实         「客户提供门卫代收的现场照片，签收人「张」实为门卫代签，客户本人未取件」（重跑）
       重跑后         **已拦截**（新记录横幅「已拦截，未执行任何处置」）
       原案台账       状态 doing / 记录 3 条 / 带快照

  ▸ 为什么不翻：签收事实在物流记录里，金额口径不因文字改变。
    所以人工跟进的常见终点是**结单或转二线**，而不是「写了就过」。
    这条边界写进了 README 与界面文案，避免把它误当成「人工覆盖」。
  ▸ 反过来说，这也证明「重新处置」不是走个过场：它**真的会得出不同结论**
    ——条件够了（M08）就翻案，条件不够（M02 / M07）就照旧拦。

【九】结论

  1. 「已转交专人跟进」从一句话变成了一件能做的事：接手 / 记录 / 等补充 / 转交 / 结单，
     全部落台账、带作者与时间、按时间线累积；
  2. **「按补充事实重新处置」是真重跑**：实测 M08 补上订单号与诉求后，
     原判「需补充信息」的案子真的走完六步并执行退款 —— 人工补的事实被引擎用上了；
  3. **它不是后门**：M02 / M07 补事实后仍判拦截，写进去的是事实，判断归引擎与授权闸；
  4. 台账连着案子与结果一起存（`case` + `run_case`），刷新之后台账、原案、
     重新处置的结果、跟进人署名**四样都还在** —— 不再有「记录还在、案子没了」这种断头路；
  5. 无回归：门禁 8/8、术语卫哨多视图 clean、单文件版行为与服务端版一致。
