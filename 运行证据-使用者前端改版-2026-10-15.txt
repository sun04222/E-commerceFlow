运行证据 · 使用者前端改版（2026-10-15）
================================================================

背景
----------------------------------------------------------------
Sun 指出前端混入大量工程描述（src/gate.ts、--gate、offline_rule、
aftersales.decide_refund、GOLD/BAD/AMBIGUOUS、退出码），要求：
「参考一下别的github电商agent相关项目学习一下然后重新做一版出来，
  我要可以直接展示而且不需要你把工程的东西全部写进去，
  我要的是面对使用者的一个前端」。

研究（三个真实 GitHub 项目）
----------------------------------------------------------------
1. Diudiu-AI-product/ai-customer-service-workbench（AI 智能客服协同工作台）
   - 主张：「把 AI 放进真实的客服工作流里，而不是做成单独的聊天机器人」
   - 对话中心 = 多会话队列 + 当前会话详情 + 建议回复 + 人工接管/升级动作
   - 回复建议是「可采纳、编辑、拒绝」的 Copilot，不是自动发送
   - 右栏按会话类型动态切换上下文面板
2. 8002-zyh/ai-ecommerce-agent-platform（B2B 电商运营平台）
   - 使用者看到的是：回复草稿、引用来源、风险标记、人工审批、处理记录
3. thiagonatandev/openai-ecommerce-agents（OpenAI 官方 demo 衍生）
   - 对话式 + guardrails 可视化 + 多 agent 分工

共识结论：面向使用者的电商 agent 前端 = 客服工作台（会话队列 / 对话流 /
AI 建议面板），术语全部业务化；工程细节（trace/eval/工具注册表）不进前端。

改版形态：售后 Agent · 客服工作台
----------------------------------------------------------------
三栏布局：
- 图标轨（深色）：主题切换、建议面板收合
- 会话队列：统计（已处理/待人工审批/已拦截/待补充信息）+ 8 个演示会话
  （业务名 + 客户原话摘要 + 状态徽章）+ 演示设置（判定方式/自动确认/
  关闭合规复核）
- 对话流：客户原话气泡 + Agent 回复气泡 + 六步处理进度条
  （理解需求→核实订单→拟定方案→合规复核→审批确认→回复客户，
   完成/未通过/未进入三态）+ 底部输入框（粘贴客户原话，回车处理）
- 处理建议：状态横幅（已处理·建议退款 ¥389.00 / 待人工审批 / 已拦截 /
  待补充信息）+ 处理结论 + 核实依据 + 合规复核 + 审批 + 建议回复（可复制）

术语映射（内部枚举 → 使用者语言）：
  PASS→复核通过；REJECT_FACT_CONFLICT→未通过：信息与记录不符；
  REJECT_AMOUNT→未通过：退款金额超出实付；CLARIFY_NEEDED→需补充信息；
  WARN_AMBIGUOUS→基本通过，有不确定项
  EXECUTE→已自动处理；ASK→已确认后处理；APPROVE→待人工审批；AUTO→无需审批
  full→完整核查；light→快速处理；clarify→待澄清
  orders/refunds/sku_specs/logistics/tickets→订单/退款单/商品规格/物流/工单记录
