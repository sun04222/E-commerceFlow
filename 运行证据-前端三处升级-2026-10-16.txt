一、改了什么（三处）
────────────────────────────────────────────────────────────────────────────────

① 窄屏不再「丢能力」
   改前：@media (max-width:1180px){ .side{display:none} } / (max-width:900px){ .queue{display:none} }
   改后：两栏在该断点变成「可临时唤出的抽屉」——
         · 图标轨新增 #navDrawerSide（≤1180 出现）/ #navDrawerQueue（≤900 出现）
         · 唤出后 .side.open / .queue.open 以 position:absolute 挂在 .body 上
           （遮罩 .mask z-index 44、抽屉 45）
         · 收回方式四种：遮罩点击 / Esc / 面板右上角 ✕ / 再点一次入口
         · window resize 拉宽后自动收（宽屏那栏本来就回来了）
         · 窄屏下点队列项 → 自动收抽屉（选完就该看见正文）

② 右栏默认态 + 工作台卡片主次
   改前：未选中案子的右栏只有一句「选中左侧一条处置记录」，占 1/4 屏零信息；
         工作台三块卡片同一重量，人得逐块读完才知道哪块要自己动手。
   改后：右栏默认态 = 处置概览（三块可点数字 + 四行可执行入口），
         页签名在「处置概览 ↔ 处置详情」之间切换；
         需要人动手的两块（等你拍板 / 等你接手）加左侧 3px 色条 + 标题提色，
         纯汇报的「数据已接入」「最近的处置」保持安静。

③ 慢通道的等待反馈
   改前：模型通道一条 20–30 秒，整段等待只有一个转圈，看不出在动、也退不出来。
   改后：六行骨架 + 一条不定进度线 + 已等待时长（逐秒）+ 取消按钮。
         · 骨架只表示「在跑」，不预置「目前进行到第几步」
           —— 服务端没有告诉我们进度，界面上就不该编一个
         · 取消只声称做到的事：「不再等它的结果」，不断言服务端没在继续跑
         · prefers-reduced-motion 下动画自动降级

④ 顺手收掉两处信息纯度缺口（属分析第②层）
   · 数据源右栏「协议 mcp（stdio）」→「取数方式：本地服务直连（mcp/stdio）」
     （标识以代码形式附上，与数据源页其余集成标识同一处理方式）
   · 单文件版「是否问了人」原先直渲引擎内部凭据 human(脚本自动确认)
     → 渲染净化层新增三条映射，数据层原样不动

九、本次没做的那一层（如实说明）
────────────────────────────────────────────────────────────────────────────────

分析里列出的第 ④ 层「无障碍与键盘可达性」本轮未动，实测现状照录：
  aria-* 0 个 / focus-visible 0 个 / alt 0 个 / role= 1 个 / tabindex 1 个
  键盘路径只有 Enter 提交（其余交互依赖鼠标点击）
影响：读屏与纯键盘用户基本无法使用本界面。
为什么先不做：这一层要么系统性重做（给每个交互元素补语义与焦点环），
要么做了也只是零散几处、反而给人「已经支持无障碍」的错觉。
留作独立一轮，做就做全。
