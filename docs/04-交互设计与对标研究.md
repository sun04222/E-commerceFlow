# 04 · 交互设计与对标研究（自主执行 Agent 桌面端）

> 本文件记录「把售后 Agent 改造成可直接对话、对话后立即自主执行」这一版前，对真实开源项目与
> Agent 交互设计文献的研究结论，以及由此确定的界面决策。**结论先于实现，避免又一次凭直觉画界面。**

## 一、为什么要重做

上一版是「样本列表 + 五个视图 + Copilot 问答」的**分析型看板**：使用者要先挑样本、再切视图、
再看轨迹，本质是给工程师看验证结果的界面。产品要求变了：

- 目标使用者是**一线售后运营**，不是研发；
- 交互必须是**对话式**：贴一句客户原话 → Agent 自己跑完全程；
- 不许**反复询问用户**确认，但要**真的有人工审批环节**（大额/高风险必须过人）；
- 体验对标 WorkBuddy 这类产品：Agent 自己推进、自己执行、把过程与结果摊开给人看。

## 三、对标研究：人工审批与 Agent 界面范式

| 来源 | 结论 | 我们采用什么 |
|---|---|---|
| 人工审批控制台设计（htmlpage.cn） | 控制台必须回答 4 问：**为什么停在这里 / 依据是什么 / 我能做什么 / 做完会怎样**；顶部先给「当前决策卡片」，不要一进来堆日志 | 审批卡四段式：停办理由、判断依据、可执行操作、**批准与驳回各自的后果预览** |
| Superkind《Human-in-the-Loop》 | **Show the action, not the model**（大白话说清将要发生什么）；理由一段话足够；**驳回与批准同样一键且带理由输入框**；**把 Agent 考虑过但否决的备选也列出来**（最有效的去偏手段）；审计留痕实时可见；**常驻停止开关** | 审批卡用业务话术描述动作；给「驳回并填写理由」；把复核的**不确定项/告警项**摊开列示；全动作留痕（审批人/结论/时间） |
| Mavik Labs《Agentic UI Patterns 2026》 | 三种协作模型：HITL（不确定才停下）/ **Human-on-the-loop（监管看板：处理量、成功率、异常数、暂停与调边界）** / 委派（给目标，Agent 执行） | 默认走 **Delegation + HITL 例外**：常规自主跑完，例外才进审批队列；顶部给**监管指标条** |
| Miądowicz《Agentic UX》 | Cursor 3 的 Agents Window：**界面隐喻不是「与助手聊天」，而是「管理劳动力」**；进度透明要给「已做什么 / 正在做什么 / 接下来做什么」——**这不是调试日志，是监管界面**；**可中断性是一等公民**（暂停/接管/回滚放顶层） | 执行流按「已完成 / 进行中 / 接下来」组织；**暂停自主执行**放顶层可见，不埋进设置 |
| VP0《HITL Approval Swipe UI》 | **按可逆性校准闸门**：只读/可逆的放行不打断，破坏性/对外的入队待批；卡片必须承载真实后果；**驳回要学原因而不是静默重试** | 只读查询零打扰；大额资金动作必过审批；驳回理由写入结单说明 |

## 四、由此确定的界面决策（本版）

1. **三个使用者问题，界面上必须一眼可答**：我的 Agent 现在在干什么、它自己做完了多少、有哪些在等我拍板。
2. **入口是对话，不是表单**：主区底部一个输入框，贴客户原话回车即跑；也能直接用预置的 8 条真实场景。
3. **执行过程可见但不做工程暴露**：以业务动作叙述（核实订单 / 调取退款单 / 比对物流 / 合规复核 / 授权判定 / 执行处置 / 回复客户），可展开看细节，但**不出现工具名、枚举、规则编号、退出码**。
4. **自主边界写在界面上**：金额分档（≤100 自动执行、≤500 自动确认后执行、>500 人工审批），让人知道 Agent 的权力范围。
5. **审批中心是一等公民**：待审批卡 + 批准 / 驳回（带理由）+ 批准后 **Agent 自动继续执行并结单**（不需要人再点第二次）。
6. **监管指标条**：今日自主处理 / 待人工审批 / 已拦截 / 需补充信息——数字必须真实聚合（上一版四张卡恒为 0 是缺陷，本版修掉）。
7. **顶层「暂停自主执行」**：开关打开后，新的咨询不再自动执行，全部转入待审批队列。
8. ~~**目标使用者与场景写在首屏空态里**~~ → **已被推翻（2026-10-15 下午）**：Sun 明确「一个成熟的 agent 不用去告诉别人这些，只要他自己可以做就行了」。首屏不再自我介绍，改为**工作台**（数据已接入 / 等你拍板 / 等你接手 / 最近的处置），目标使用者与场景移回本文档。
9. **Agent 交不出来的案子必须有人能接手**（2026-10-15 晚补，Sun：「这个人工跟进你这个里面应该也要可以进行操作，就是人工可以直接在里面跟进」）——被拦截 / 需补充信息 / 审批未通过这三类案子，上一版只显示一句「已转交专人跟进」，人看着这句话**没有任何地方可以动手**，等于把球踢给了空气。这是对 HITL 文献里 **Human-on-the-loop** 的落地：例外一旦发生，接手动作必须和审批动作一样实在。做法见第七节。

## 五、目标使用者与典型场景（产品定位）

**目标使用者**：中小电商商家的**售后运营 / 客服主管**（1–10 人团队，日处理售后咨询几十到几百条）。
他们不写代码、不看轨迹、不关心工具名；他们关心的是「今天有多少条自己处理完了、有没有判错、有哪几条等我点头」。

**典型场景**：

1. **日常批量处置（主场景）**：把客户消息逐条贴进来或对接进队列，Agent 自动完成核实订单 → 调取退款单 → 比对物流 → 判责 → 合规复核 → 执行处置 → 生成回复，**小额自动执行、大额自动转入审批**，人只需要处理审批队列。
2. **高风险例外（审批场景）**：金额超过自动执行上限、或责任归属没有确定口径（代收点签收、破损责任不清）时，Agent 停在该步并生成一张审批卡：说明停办理由、依据、批准与驳回各自的后果，由人工一键裁决；裁决后 Agent 自动继续并结单。
3. **对账与复盘（监管场景）**：随时看今日自主处理量、被拦截数、待审批数；每条会话都能回看「Agent 当时看到了什么、依据什么下的结论」。

## 六、落地结果与实测验收（2026-10-15）

上面的八条界面决策全部落到 `desktop/public/index.html`，并用真实 Chromium 逐项断言（完整输出见
根目录 `运行证据-自主处置台改版-2026-10-15.txt`）：

| 决策 | 落地形态 | 实测证据 |
|---|---|---|
| ①三个问题一眼可答 | 顶栏监管指标条：已自动处理 / 待人工审批 / 已拦截 / 审批未通过 / 需补充信息，五档实时聚合，**每一项可点** | 空态全 0；跑完 M01 后「已自动处理=1」；跑 M03 后「待人工审批=1」 |
| ②入口是对话 | 主区底部输入框「粘贴客户原话，回车即处理」＋ 左栏「试一条真实场景」8 条预置 | 8 个预设按钮就位；贴原话与点预设走同一条链路 |
| ③过程可见但不暴露工程 | 六步执行流（理解需求 / 核实订单 / 拟定方案 / 合规复核 / 授权与执行 / 回复客户）三态 + 可折叠细节 | M01 六步全 done；M03 第五步停在「停办」态 |
| ④自主边界写在界面上 | 首屏空态「自主边界」卡：≤¥500 自动、¥100 直接执行、>¥500 人工审批；审批卡亦复述该上限 | 审批卡正文：「该笔处置金额 ¥1299 超出 Agent 可自动处置上限 ¥500」 |
| ⑤审批中心是一等公民 | 审批卡四问：停办理由 / Agent 的判断依据 / 它拿不准的地方 / 批准与驳回分别会发生什么，下接审批人与驳回理由输入 | 批准 → 真实执行并结单（回复「已通过人工审批」）；驳回 → 未执行、转专人（回复「经人工复核后未予通过」） |
| ⑥指标必须真实聚合 | 指标由会话结果状态机推导，非预置数字 | 七轮场景跑下来五档数字全部与案件实际归属一致 |
| ⑦顶层暂停自主执行 | 顶栏「自主执行 已开启」开关 | 关闭后跑 M01（原直接执行档）→ 转入待人工审批，审批卡数量=1 |
| ⑧定位写在首屏 | 空态三卡：给谁用（售后运营 / 客服主管，1–10 人团队）/ 怎么用 / 自主边界 | 首屏可见，帮助弹层 `?` 可再展开 |

**额外修掉的三个真实缺陷**（都是实测发现的，不是设计时想到的）：

1. **审批单号是系统码**：原 `APR-<base36>` 是工程前缀，被术语卫哨抓到。改为业务化日期单号
   `YYYYMMDD-NN`（如 `20261015-01`），界面上显示为「单号 20261015-01」。
2. **驳回被算进「已自动处理」**：驳回后 `executed_tool` 为空但复核裁决为通过，原状态机会把它归入
   「已处理」档，指标语义错误。新增独立状态 `审批未通过`（含队列徽章、结果卡横幅、第五步执行流
   文案），驳回案件的处置说明为「人工审批未通过，未执行任何资金处置」。
3. **指标条是只读的，点不动**（Sun 指出）：「今天有多少条在等我」答了，「点进去处理」没答。
   指标条从展示件升级为**监管入口**：

   | 交互 | 行为 |
   |---|---|
   | 点任一指标 | 左侧队列按该状态筛选，并**自动选中第一条**，右栏立刻给出这单的结论与可复制的客户回复 |
   | 点「待人工审批」 | 除了筛选，**直接把人送进人工审批中心**（同一档唯一需要人动手，别让人再找一次入口） |
   | 再点同一个指标 | 取消筛选（切换语义，不需要额外的「返回」按钮） |
   | 清除筛选 | 队列头部的 `筛选自 N 条记录` ＋ 「清除筛选」 |
   | 计数为 0 的档 | 数字淡显，点进去给空态提示而不是一片空白 |
   | 新跑一条咨询 | 自动清空筛选，避免「刚跑完的这条不见了」 |

   实测：4 条记录（完成/拦截/补充/待审批各 1）下，点「已拦截」→ 队列 4→1 且只剩对应那条；
   点「待人工审批」→ 视图切到审批中心且审批卡 1 张可裁决；再点同一指标 → 回到 4 条；
   在只有 1 条拦截记录时点计数为 0 的「已自动处理」→ 空态 + 筛选标签。四个视图术语卫哨全 clean。

## 七、Windows 一键启动器为什么是纯 ASCII（2026-10-15 实测）

`启动桌面端.cmd` 原先是 UTF-8（无 BOM）＋ 文件内 `chcp 65001`，在中文 Windows 的默认代码页
（936，也就是双击时的环境）下**起不来**：输出里出现 `'mjs' 不是内部或外部命令`、
`'新服务，端口被占用时会留下一个报错的最小化僵尸窗口。' 不是内部或外部命令` ——
本该是注释和整行的语句被拆成了碎片。

最小用例复现（5 行）把根因钉死了：

| 文件 | 内容特征 | 结果 |
|---|---|---|
| A | UTF-8 ＋ 文件内 `chcp 65001` | **紧跟在 `chcp` 之后的那一行被丢掉**（`MARK1` 没执行，`MARK2` 执行了） |
| B | GBK ＋ 不写 `chcp` | 所有行完整执行 |

结论：**`chcp` 写在批处理文件里会让 cmd 的行解析错位**，与文件是 UTF-8 还是 GBK 无关；
而只要文件里存在非 ASCII 字节，代码页一旦对不上，多字节序列甚至可能吞掉换行、把后面的行
当成独立命令执行。

所以启动器的取舍是：**文件保持纯 ASCII**，说明文字一律英文，注释里写明原因防止后人「优化」回去。
同批修掉的另一处：等待端口原来用 `timeout /t 1`，该命令在 Git Bash / MSYS 环境下会被 GNU
`timeout` 顶掉（实测报 `invalid time interval '/t'`），改用 `ping -n 2 127.0.0.1 >nul` 等待。

> 这是「可移植性 vs 观感」的取舍：一行中文提示换不来启动可靠性。要中文提示，就在 README
> 里写，别写进 `.cmd`。`启动桌面端.sh`（macOS / Linux）不受影响，保持中文注释。

## 八、人工跟进：从「一句话」到「一件能做的事」（2026-10-15 晚）

**问题**（Sun 指出）：被合规复核拦下、诉求没说清、审批被驳回的案子，界面只给一句
「已转交专人跟进」。这句话在**动作上是空的** —— 人看不到自己该在哪动手、做了什么、
做到哪一步了。跟「审批只有一个『待审批』标签、点不进去」是同一类缺陷：**把状态当成了功能**。

**对标依据**：HITL 文献里 Mavik Labs 的 Delegation + HITL 例外、以及 Human-on-the-loop
监管指标，共同的要求是「例外必须可接管、接管过程必须留痕」。Superkind 的
"show the action, not the model" 在这里同样成立：跟进面板要展示的是**动作**（认领、记录、重跑、结单），
不是一句关于动作的描述。

**落地：跟进台账（右栏，只在需要人接的案子上出现）**

| 能力 | 为什么必须有 |
|---|---|
| 接手署名认领 | 「谁在跟」是跟进的第一个事实；没有它，台账只是一堆无主的记录 |
| 记一条跟进（时间线、带作者与时间） | 客服的真实工作就是**累积沟通记录**；交接靠它 |
| 已联系客户 / 等补充 | 把「球在客户那边」和「球在我这边」区分开 |
| 转交二线（跟进人随之改） | 一线解决不了的要能往上走，而不是原地挂着 |
| 核实完毕，结单 | 有始必须有终，否则列表会烂掉 |
| **按补充事实重新处置** | 最关键的一条：人工补到的事实要能**被引擎用上**，否则跟进永远只在界面里打转 |

**「重新处置」的设计取舍（重要）**：它是**真的重跑**——把「客户补充/人工核实的事实」拼进
原始诉求，再走一遍完整链路（取证 → 复核 → 授权闸），不是人工直接改结论。
- 好处：口径只有一套。人工写进去的是**事实**，判断仍然归引擎与授权闸，
  不会出现「人工写了就能过」的后门。
- 代价：补充的事实能不能改变结论**不由人决定**。实测 M02 补「门卫代签、本人未取件」后仍判拦截
  （签收事实在物流记录里，不因客户的新说法消失）。所以人工跟进的常见终点是**结单或转二线**。
- 这条边界写进了 README 与界面文案，避免把它误当成「人工覆盖」。

**发现并修掉的一个断头路**：跟进台账一开始只存「跟进记录」，重新打开页面时会出现
**「台账还在、它记的那条案子没了」**（案子的会话在页内内存，台账在服务端）。修法与
`docs/05` 界面决策第 9 条的刷新接续同源：每次跟进操作时把该会话的**瘦身快照**
（标题 + 客户原话 + 结果，去掉轨迹）一起存进台账，启动时按 `case_key` 把案子补回队列。**同一个 key（消息号）在入站、跟进台账、
重跑三处必须一致**——否则就会出现「记录挂在 A 上、案子显示成 B」。

**同一类断头路的第二处（本轮补掉）**：只还原**原案**还不够。「按补充事实重新处置」产出的是**另一条**记录
（`诉求不明（已重新处置）`），它同样活在页内内存里 —— 刷新后原案回来了、**人自己跟出来的结论却没了**，
等于白跟一场。修法：`rerun` 时把新结果的瘦身快照也随台账存（`run_case`），启动时一并还原；
重跑记录的会话 id 用**稳定值** `frun-<case_key>`（而不是带时间戳），这样同一案子只留**最近一次**结果、
还原也天然幂等（不会刷新一次多一条）。实测刷新后队列 2 条（重跑记录 + 原案）、台账 `M08=closed(3)`、
点开重跑记录状态「已处理」/ 案件类型「仅退款」/ 六步 6 全在。

**由此得到的一条通用规则**：只要某个动作**产出了新东西**（不只是改了已有记录的字段），
就必须把这个新东西也纳入持久化范围。只持久化「被操作的对象」而漏掉「操作的结果」，
就会出现「历史在、成果不在」的假接续——它比彻底不接续更糟，因为它看起来是接上了。

## 九、窄屏、默认态与等待：三处「能力不该跟着窗口和耐心一起消失」（2026-10-16）

起因是做了一次前端实测盘点，量到几处「看起来完整、用起来缺角」的地方：`aria-*` **0 个**、
`focus-visible` **0 个**、`transition` **仅 3 条实体**、`@keyframes` **仅 2 个**。从四层里挑了三处
能真跑通、且**不破坏原有四区信息架构**的落地。

### 1. 窄屏不是「少给能力」，是「换个拿法」

改前两行媒体查询：`≤1180px` 直接 `.side{display:none}`、`≤900px` 直接 `.queue{display:none}`。
**能力跟着窗口一起消失**——而在窄窗口里，人恰恰更需要看队列和详情。

改成**可临时唤出的抽屉**：图标轨上多两个入口（只在各自断点出现），唤出后两栏浮在正文之上
（`position:absolute` 挂在 `.body` 上，遮罩 44 / 抽屉 45），收回有四种方式（遮罩 / Esc / ✕ / 再点入口），
窗口拉宽后自动收。**窄屏下点队列项自动收抽屉**——选完就该看见正文，而不是还要人再关一次。

- 保留的：容器够宽时两栏各自归位，与之前完全一致。
- 代价：窄屏同一时刻只能看一栏。这是取舍不是缺陷，已写进「交付说明」已知边界。

### 2. 默认态不该是空白，卡片不该同一个重量

右栏在没选中案子时只显示一句「选中左侧一条处置记录」——**占 1/4 屏却零信息**，这是最容易
改、收益最直接的一处。改为**处置概览**：三块可点数字（已自动处理 / 待你拍板 / 待你接手）
+ 四行可执行入口（处理人工审批 / 接着跟进 / 贴一句客户原话 / 接入数据源）。页签名随之在
「处置概览 ↔ 处置详情」之间切换——**栏目自己要能说明现在是什么状态**。

工作台三块卡片原先是同一个重量，人得逐块读完才知道哪块要自己动手。现在给**需要人动手的两块**
（等你拍板 / 等你接手）加左侧 3px 色条与标题提色，纯汇报的（数据已接入 / 最近的处置）保持安静。
这条和「指标必须能点」是同一个道理：**界面上最重的那块，应该是要人动手的那块**。

### 3. 等待期间：给结构、给时长、给出口，但不编进度

模型通道一条 20–30 秒，原先整段等待只有一个转圈——看不出在动、也退不出来。给三样：

| 给什么 | 怎么给 | 为什么这样给 |
|---|---|---|
| 结构 | 六行骨架 + 一条不定进度线 | 只表示「在跑」。**服务端没有告诉我们跑到第几步，界面上就不该编一个** |
| 时长 | 已等待秒数逐秒增长 | 人对着计时器和对着转圈的耐心是不一样的 |
| 出口 | 取消按钮 | 20–30 秒的等待必须能退出 |

**关于「取消」的口径**：前端能真正中止的是**等待**这件事本身（本地请求订阅了中断信号；
单文件版没有网络调用，用页内标记忽略迟到结果）。如果那条处置在服务端已经跑完，它的结论仍会
照常落到审批队列与决策日志里。所以提示语写的是「已取消等待，不再等它的结果」——
**不假装能撤回已经发生的事**。这和 `docs/05` 里「握手失败不假装、集成能力宁标缺不欺骗」是同一条纪律。

### 4. 顺手收掉的两处信息纯度缺口

- 数据源右栏的「协议 mcp（stdio）」→「**取数方式**：本地服务直连（`mcp/stdio`）」。
  先讲人话，再把对接人才看得懂的标识以代码形式附上（与数据源页其余集成标识同一处理方式）。
- 单文件版「是否问了人」原先直渲引擎的内部凭据 `human(脚本自动确认)`。在**渲染净化层**加三条映射
  （`按预设自动确认` / `人工未响应` / `人工`），**数据层原样不动**（实测 `result.auth.approver`
  仍是原值，界面上是人话）。

**这里有一条容易走偏的界线**：术语卫哨豁免 `<code>` 节点，本来是「让必要的集成标识能被披露」，
如果拿它去把**业务视图**里的工具名盖住，那不是修界面、是绕过检查。
所以本轮的处理顺序是：**先问这句文案该不该出现在这里**（题干），再决定标识放哪儿（呈现）。
「是否问了人」这一行的问题不在括号里那串字，而在它把一个内部凭据直接当成了给人看的答案——
所以改的是映射，不是把它塞进 `<code>` 让它消失。

### 5. 本轮没做的那一层

无障碍与键盘可达性未动（`role` 全页仅 1 个、键盘路径只有 Enter）。这一层要么系统性重做，
要么做了也只是零散几处、**反而给人「已经支持无障碍」的错觉**。留作独立一轮，做就做全。

### 6. 「去跟进」曾经是假动作：状态词配了按钮，按钮却没接到地方（2026-10-19）

**症状**：结果卡横幅上明明写着「已拦截，未执行任何处置」，右侧还挂一个「去跟进」按钮 ——
点了没反应。不是没绑事件，而是绑错了：它只做 `#fuPanel.scrollIntoView()`。

**为什么这一点点差别是致命的**。`#fuPanel` 只在「选中一条、且这条需要人工跟进」时才渲染，
且它住在右栏里。于是三种情形下按钮必然空转：

| 情形 | 面板在不在 | 原实现的结果 |
|---|---|---|
| 在数据源页 / 审批页 | 不在（右栏换成了别的内容） | 静默无反应 |
| 没选中任何案子 | 不在（右栏是概览） | 静默无反应 |
| 窄屏（≤1180） | 在，但右栏是 `display:none` 的抽屉 | 对着隐藏元素滚动 = 什么也没发生 |

**根因不是一处 bug，而是「入口各自实现」**。同一个词「去跟进」当时有两个属性、两套语义：
`data-goto-fu`（滚一下右栏）与 `data-open-fu`（跳到第一条待接手）。入口一多，
总有一个会漏掉「窄屏右栏是抽屉」这一层 —— 而漏掉它的那个，恰好是用户第一眼会点的那个。

**改法：把跳转收敛成一个唯一入口，并给它一个可检查的地址。**

1. `gotoFollowUp(ref)` 是**唯一的导航函数**，四个入口（结果卡横幅 / 回复区提示 / 队列跟进标签 / 右栏概览）只准调它，不准自己 `scrollIntoView`。
2. `ref` 带上**这条案子自己的标识**（案件主键）。不带标识就只能「跳去第一条待接手」——那不叫去跟进，那叫碰运气。
3. `revealFollowUp()` 负责「送进眼里」：宽屏滚动右栏；**窄屏先唤出右栏抽屉再滚**，否则滚的是一个还没布局的元素。
4. 加一层极薄的**哈希路由**（`#fu/<案件主键>` / `#approvals` / `#sources`），并且只允许两个方向流动：`renderAll()` 末尾把状态写成地址（`replaceState`，不污染浏览历史），启动与 `hashchange` 时把地址读回状态。这样刷新、粘链接都能落回同一处。
5. 队列里的跟进标签从 `<span>` 改成 `<button>` —— 它本身就是入口，而且必须排在 `data-q` 之前判定（标签嵌在条目里面，先判 `data-q` 就只会选中条目、跳不进去）。

**验收（成对证据，缺一不可）**：两条不同的案子（M02 / M07）分别点各自的「去跟进」，
落点必须各是各的 —— 实测 `clickedKey=M07 → hash=#fu/M07 → activeRow=M07`、
`clickedKey=M02 → hash=#fu/M02 → activeRow=M02`；窄屏 1100 点一下 → `sideOpen=true / maskOn=true / panelInView=true`；
从数据源页点队列标签 → 回到处置页并落到该条；带 `#fu/M07` 重开 → `queue=2 / activeRow=M07 / panelInView=true`。

**留给别的项目的教训**：**「状态词 + 一个按钮」不算交互闭环，要能回答「点了之后落到哪、从任意入口点是否都落到同一处」。**
凡是「跳到某处」的按钮，先把它抽成一个函数，再谈样式。

### 7. 配置搬进界面之后暴露的三件事（2026-10-21）

模型通道原先只写在项目根 `.env`：改一次密钥要找到文件、打开、改、**还要记得重启**（`src/env.ts` 有模块级缓存）。
把四条配置搬进界面（图标轨滑杆入口 / `#config`）时，真正值得记的不是表单，是三件容易做错的事。

**一、界面上不出现完整密钥，也不靠「不显示」来保证。**
回显只有末 4 位（`****ka0a`）；输入框留空表示沿用原值，要清空必须单独勾 —— 不能让「没填」等于「清掉」；
连通测试失败时，服务商返回的错误消息里若夹带密钥，先替换成 `***` 再回给前端。
密钥这一层的成本不在展示，在**每一条出口都要过一遍**：接口、界面、错误消息、日志。

**二、「填齐了」和「连得上」必须分成两档说。**
配置完整 ≠ 通道可用。角标三档：`未就绪`（缺项 / 占位值）→ `已填齐`（四项齐全，**没验过**）→ `连通已验证`（真跑过一次补全）。
只要把这两件事混成一档，用户就会在「明明配好了却用不了」的时候开始怀疑整个系统。
同理，「测试连通」做的是**一次真实调用**，不是探活：通就报延迟与回复，不通就原样报错误原文 + 三条常见原因，绝不吞掉。

**三、直接打开地址进不去，是「渲染抢在路由前面」的典型病。**
`boot()` 先渲染一帧，而渲染末态的 `syncRoute()` 会把当前状态投影成地址 —— 于是首帧把地址栏里的 `#config` 抹成空，
等 `applyRoute()` 去读时地址已经没了。症状很迷惑：**点进去能到，贴链接进不去**。
改法是一个很薄的闸：读回地址之前，禁止渲染覆盖地址（`routeSynced`），读回之后再用状态对齐一次地址。
顺带把另一种不一致也收掉：地址被清空 → 回默认视图；地址指向一条不存在的案子 → 用当前状态覆盖它，**不留一个骗人的地址**。

**留给别的项目的教训**：**「状态 → 地址」和「地址 → 状态」同时存在时，必须明确谁是启动那一刻的主人。**
默认答案是地址 —— 因为它来自用户，而状态只是内存里的一帧。
