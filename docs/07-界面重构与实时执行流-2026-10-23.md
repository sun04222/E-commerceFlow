# 07 · 界面重构与实时执行流（2026-10-23）

> 本文回答三个问题：**为什么要改**（原界面的具体问题，带证据）、**改成了什么**（方案与取舍）、
> **凭什么说改好了**（逐项验收底线）。所有数字都来自本轮的实测，原始回执见
> `运行证据-界面重构与实时执行流-2026-10-23.txt`。

## 一、诊断：原界面的问题不是「不好看」，是**信息顺序错了**

原版（`cs2-*` 截图那一版）的骨架是对的——三栏、指标条可点、审批四问——所以本轮**没有推翻骨架**，
只动了三处真正影响使用的顺序与可达性。逐条说清依据：

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **结论被压在过程下面** | 一次 M01 处置：六步执行流 6 行 × ~70px ≈ 430px，结论卡与客户回复被推到首屏之外 | 打开一条案子，第一眼看到的是「第 2 步做了什么」，而不是「这事办完了没有」。这是**顺序**问题，不是样式问题 |
| 2 | **过程是「补写」的，不是「长出来」的** | `runQuery` 里 `await new Promise(r => setTimeout(res, 150))` 逐行点亮，共 6 拍 | 等待 20–30 秒（模型通道）期间界面只有一个转圈；最后 1 秒才把已经算完的结果分 6 拍放出来。**等待与过程脱节**，且那 6 拍是纯装饰 |
| 3 | **键盘与读屏整层留白** | 全页 `role` 仅 1 个；键盘只有 Enter 与 Esc；无 `aria-live`、无焦点陷阱、无跳转链接 | 审批类界面在键盘上不可用是真实缺陷（docs/04 已把它列为留白，本轮补齐） |
| 4 | 队列只能靠眼睛找 | 无搜索；无分组；`j/k` 不存在 | 一天几十上百条时，找一条只能滚 |

另外两处是「顺手会踩到」的小坑，一并修掉：选中项底色偏蓝，灰字在其上从 4.5:1 掉到 **4.16:1**（实测）；
抽屉在宽屏下也挂着 `role=dialog` 的写法会误导读屏（本版改成**角色跟着状态走**）。

## 二、方案：三件事，按信息顺序重排

### 2.1 结论在前、过程在后（信息架构）

```
客户原话
  └─ 结论卡        一句话：办完没有 / 多少钱 / 下一步点哪
  └─ 内联审批卡    仅「停办等人」时出现（紧贴结论，因为它等的就是人）
  └─ 执行过程时间线 六步 × 真实事件 × 真实时长 × 可展开依据
  └─ 结果详情      处理结论 / 授权与执行 / 给客户的回复（可复制）
  └─ 输入框
```

**依据**：审批控制台类界面的第一性原则是「先给可裁决的结论，再给可追问的依据」。
把过程放前面，是把「可追问」放在了「可裁决」之前——顺序反了。

### 2.2 执行流改成事件驱动（本轮的核心能力，不只是 UI）

**引擎侧**：决策轨迹本来就是这条链路的真实审计记录（`src/trace.ts`，每步一行 JSONL）。
本版让它同时充当**进度事件源**：

- `Trace` 增加 `onEvent` 旁路（宿主抛错不影响引擎，引擎也从不依赖有没有人听）；
- `RunOptions` 增加 `onEvent` 与 `signal`；
- 编排层在 5 处**环节边界**加 `trace.checkpoint()`：受理前、每次取证前、判据归纳前、补证轮次前、
  **资金动作之前**。

**传输侧**：新增 `POST /api/run/stream`（NDJSON：`start` → 逐条 `event` → `result`）。
它与 `/api/run` **共用同一份 `prepareRun` / `finishRun` / `runOptionsFor`**——
两条交付路径不可能再出现「一边记账一边不记」这类口径差。头带 `X-Accel-Buffering: no`，
避免被中间层攒成一次性返回。

**界面侧**：只有一处 `apiStream()`。服务端读 NDJSON；单文件版没有网络，但引擎就在同一页里跑，
回调是真发生的，接的是**同一份 `onEvent`**（构建脚本替换一条传输缝即可）。

**删掉的是假的**：那 6 拍 `setTimeout` 点亮、等待期的六行骨架与不定进度线，全部删除。
上一版 README 里那句「服务端没有告诉我们跑到第几步，界面上就不编一个」依然成立，而且更硬了——
现在显示的进度不是编的，是引擎自己的审计轨迹。步长与时长都是实测值（M01 全程约 90–170 ms，
六步各自 1–3 ms；模型通道同理，只是间隔更长）。

**顺带修好的一件事：取消变成真取消。** 断开连接（点取消 / 关页面）→ 服务端 `req.on("close")`
→ `AbortController` → 引擎在下一个环节边界抛 `AbortError`。语义写死在提示语里：
**尚未发生的动作一定不会发生；已经发生的处置不回滚**（不假装能撤回）。

### 2.3 审批做成消息块 + 键盘可达性（交互）

- **审批做成消息块而不是另一个页面**（借鉴 assistant-ui 的 `Thread/Message` 分层与
  CopilotKit 把「工具调用 / 审批」当一等可渲染消息类型的做法）：超出边界的处置就地生成四问卡，
  批准即执行并结单、驳回即未执行收口；续办句柄没了的单子不给假按钮，只给「重新处置」。
- **命令面板 `Ctrl/⌘+K`**（借鉴 Linear / Raycast / VS Code 的「动作与内容是同一份可搜索列表」）：
  动作 + 处置记录 + 示例场景合成一份列表，另有一份「快捷键一览」模式。
- **键盘路径**：`/` 聚焦输入框、`j/k`（或 ↑↓）在队列移动并预览、`Enter` 打开、`1–6` 按指标筛选、
  `?` 看快捷键、`Esc` 关面板/抽屉；面板内 `Tab` 循环（焦点不出面板），关闭后焦点回到打开它的入口。
- **无障碍**：可访问名全覆盖、装饰性图标 `aria-hidden`、结论与审批走 `aria-live` 播报、
  抽屉打开时才有 `role=dialog` + `aria-modal` 且焦点进入、正文与辅助文字两套主题都达 WCAG AA。

### 2.4 视觉系统重写（视觉呈现）

不是换皮，是把**规则**写进令牌：一处颜色只表达一件事（蓝=可点的动作、绿=已自主完成、橙=在等人、
红=被拦下/没跑通、灰=无需动作）；文字四级里 `--ink-3`/`--ink-4` 的取值**按 WCAG AA 反算**——
要在 `surface` / `surface-2` / `surface-3` 三种底色上都 ≥ 4.5:1，取最差的那个决定数值
（脚本 `.devtools/ui/contrast.mjs` 可复现）。全部动效都能关（`prefers-reduced-motion`）。

## 三、被否掉的备选（写清楚，免得下次重新讨论）

| 备选 | 为什么否 |
|---|---|
| 引入 Preact + assistant-ui 式组件分层 | docs/06 的结论是「引入机制，不引入框架」。本工程的卖点之一是**零依赖 + 单文件双击即用**；引入框架会让 `demo.html` 的构建链与「零安装」同时失效。改为在现有字符串渲染里做**分片**：`markDirty/flushRender` 之外新增 `patchTimeline`，跑批期间只重画时间线那一块 |
| 给「批准 / 驳回」加快捷键（A / R） | 金额动作不能是一个两字母误触。面板里也**不放**任何金额动作 —— 它只能在写着四问的卡上做出。这是刻意的不对称 |
| 等待期保留骨架 + 假进度条 | 有真事件之后，假形状就是噪声；而且一旦有了真进度，假进度会立刻被使用者识破 |
| 把 `index.html` 拆成 `app.css` / `app.js` | 构建脚本与「单文件」形态都以「一个 index.html」为前提；拆分的收益（可维护性）不抵风险（构建链、服务端静态路由、演示形态同时要改）。改为在文件内用分区标记，把大改通过脚本按区间拼入 |

## 五、验收底线（本版全部达成，回执见运行证据）

1. **门禁不动**：`node src/cli.ts --gate --offline` 仍 8/8、退出码 0（引擎改动是加法）。
2. **工程术语卫哨不动**：`.app` 渲染文本 0 命中（本轮还给卫哨加了 20 个新词：
  `phase` / `seq` / `ndjson` / `onEvent` / `AbortError` 等，防止新界面把技术词漏出去）。
3. **两种形态各验一遍**：服务端版与 `demo.html`（`file://` 直接打开）行为一致。
4. **声称必须有证据**：流式与取消由 `scripts/verify-stream.mjs` 断言（22 项，可反复复跑）；
  无障碍与对比度由页内探针量出数值，不靠眼看。
5. **失败要说得出原因**：断流、模型通道不可用、单文件版无进程等情形都保持原有的「如实降级」口径。

## 六、还没做的（诚实清单）

- **模型通道未在本轮实测**：本机无可用密钥，门禁与全部断言都跑在规则判定上。
  流式链路对模型模式**结构相同**（同一份 `onEvent`，只是模型调用把间隔拉长到 20–30 秒），
  但「模型模式下时间线的观感」这一条属于**未测**，不当作已验证。
- **MCP 通道在本机未联通**（子进程 `spawn EPERM`，沙箱限制），数据源页如实显示「本地文件通路」；
  这是环境限制，不是本轮回归，原有降级行为未被破坏。
- 命令面板的模糊匹配是「顺序子串 + 按空格分词」，没有拼音首字母；输入 `sj` 命不中「数据源」。
  这是有意的轻实现，等有人真觉得别扭再加索引。
- 时间线每步的时长是**客户端观测到的首末事件间隔**，不是引擎内部计时；
  文案用「ms / 秒」而不写「服务端耗时」，避免口径夸大。
