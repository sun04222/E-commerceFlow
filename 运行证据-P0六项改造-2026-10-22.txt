────────────────────────────────────────────────────────────────────────────────
一、记忆：轨迹回读 + 案件索引（src/memory.ts）
────────────────────────────────────────────────────────────────────────────────

【做了什么】
把「已经落盘但没人读」的 479 个决策轨迹会话，回读成 476 张案件卡
（案型 / 判据 / 最终裁决 / 金额 / 授权档位 / 处置结果 / 是否补证 / 客户原话），
落成 data/memory/case_index.json（299,120 字节，属派生产物，不入库）。
检索 = 规则粗筛（同案型 → 金额±30%）+ BM25（中文按二元组切词），**不引向量库**。
召回结果只拼进判据提示词（advisory），**不进授权闸**。

【为什么不用向量库】三条，写进代码注释也写在这里：
  ① 量级不对：几百张卡，BM25 召回质量完全够；
  ② 零依赖是硬约束，单文件版要能在浏览器里跑；
  ③ 这个场景最怕「说不清为什么是它」—— 每条召回必须给出人话理由
     （同属「仅退款」/ 金额相同 / 客户原话有 18 处共同措辞），
     而「相似度 0.83」在售后结论被追问时等于没说。

【检索验证：node .tmp/verify-memory.mjs】12 项断言全 PASS
  查询：一张餐桌申请退款 500，语气强硬（与 M07 同族），exclude_msg_id=M07
  · M07-2026-10-22T11:47 仅退款 ¥268 分 38.43
    判据需补充信息｜最终未通过：金额超出实付｜同属「仅退款」；金额相同；客户原话有 18 处共同措辞
  · ADHOC-987024     仅退款 ¥268 分 37.90  同属「仅退款」；金额相同；18 处共同措辞
  · ADHOC-470211     仅退款 ¥268 分 28.28  同属「仅退款」；金额相同；18 处共同措辞
  PASS 索引里有案件卡（476）
  PASS 没有「既无案型也无判据」的空卡进索引
  PASS 有案件卡带最终裁决（445/447 —— 见下「模板兜底」）
  PASS 有案件卡带授权档位（221/447）
  PASS 同案型能召回 · 条数不超 limit · 每条带人话理由 · 案型一致
  PASS 不把查询自己当参考 · 同一案子只出现一次（msg_id 去重）· 按分数降序
  PASS 记忆层不依赖授权/政策 · 授权分档不吃记忆结果（静态核对 import 与调用点）
  PASS 空文本查询不抛异常

【两个设计取舍，都是实测逼出来的】
1) 首次跑出来只有 7/447 张卡带最终裁决 —— 因为本项目在补 verdict 字段之前
   已经写了几百条真实轨迹。处理：**字段优先、模板兜底**（review 行没有
   verdict 字段时，才从 summary 的固定模板里取一次）。补完 445/447。
   反过来也不行：只认 summary 太脆，改一个标点就全崩，所以它只能当兜底。
2) 同一案子重跑（补事实重跑 / 审批后重跑）会产生多张卡。首版没去重，
   「参考了 3 条」里可能有 2 条是同一个案子的两个旧版本 —— 等于没参考。
   处理：cards 按时间倒序，同一 msg_id 只留第一张（最近一次）。

【轨迹留痕】新增三个字段，不许再从 summary 里正则抠字符串：
  judge 行 detail.judge_source / auth 行 detail.tier / review 行 detail.verdict
  实测服务端版一条 M01 的轨迹里：
    judge  | 判据归纳完成（来源：offline_rule） | decision, amount, judge_source, ...
    review | Reviewer 裁决：REJECT_MISSING_EVIDENCE | verdict, findings, ...
    auth   | 授权分档：ASK（执行前询问） | tier, tool, amount, threshold, ...
  以及记忆自己的留痕：
    judge plan | 参考历史同类案件 3 条（advisory：只作提示，不参与判定与授权）
    {"advisory":true,"hits":[{"msg_id":"WX-12286dd3b8","score":46.89,"verdict":"PASS",
      "why":["同属「仅退款」","金额相同","客户原话有 21 处共同措辞"]}, ...]}

【界面】右栏新增「同类案子过去怎么处理的 N 条 · 只作参考」
  浏览器实测（服务端版，规则通道，贴一条与 M07 同族的话）：
    title = "同类案子过去怎么处理的 3 条 · 只作参考"
    rows  = 3
    first = "仅退款 [未通过：金额超出实付] 10-22 12:03 · ¥268
             同属「仅退款」；金额相同；客户原话有 18 处共同措辞"
    note  = "这是过去处理同类诉求留下的记录，用来了解常见的处理方式。
             本条仍按这次调取的资料与政策来判断，不受这些记录左右。"
  裁决码统一走净化层（不另立文案表）；术语卫哨 count=0；控制台零报错。
  「只作参考」写在标题上、末尾再说一遍：记忆一旦被当成判定依据，
  它就成了绕过审批的后门（金额档位只认订单账本）。

【单文件版：如实没有，不造假】
  虚拟文件系统没有目录枚举能力、浏览器里也没有历史轨迹 → 记忆块不出现。
  代码里先探一次能力（CAN_SCAN），而不是等抛异常再兜。
  实测：单文件版跑 M02 → 6 步走完、结果正常、右栏无记忆块、卫哨 0、零报错。

【本轮改崩又修好的三个真 bug（都是「服务端版看不出来」那一类）】
1) 单文件版 fs 垫片缺 appendFileSync —— 轨迹改批量写之后，第一次 flush 就崩。
2) build-demo 的模块清单是手写的，memory.ts 没进清单 —— import 被剥掉、
   导出变 undefined，整页 boot 失败（症状是示例 0 条、引擎对象不存在）。
3) trace.ts 的退出钩子直接调 process.on —— 浏览器垫片里 process 只有 env，
   于是每次处置都在构造 Trace 时抛异常。修法是不装作有退出事件：
   `typeof process === "undefined" || typeof process.on !== "function"` 直接不装兜底。
   同时 types.ts 不再反向 import memory.ts（类型定义搬到 types.ts），
   免得模块拓扑成环。

  这条是「参考不改变判定口径」的证明：带记忆跑与不带记忆跑，门禁结论一致。

二、台账落盘：人工跟进与审批单（desktop/server.mjs）
────────────────────────────────────────────────────────────────────────────────

【改了什么】
followups / pendingApprovals 从「进程内 Map，重启即清空」改成
append-only JSONL（data/ledger/followups.jsonl、approvals.jsonl）+ 启动回放。

为什么是事件流而不是快照：
  · 快照要每次重写整条记录（含案子快照与重跑结果），越写越大，写一半崩了整条坏掉；
  · 事件流每次只追加一行，坏一行只丢一行（实测解析坏行会打一行 warn 后跳过）。
更关键的一条：**写入与回放共用同一个 applyFollowupEvent()**。
  两处各写一套状态推进，运行时与重启后就会慢慢长成两套口径 ——
  这类偏差不会报错，只会让「重启前是跟进中、重启后变待跟进」这种怪事出现。

【实测一：跟进台账跨重启】
  A 进程：M02 依次 claim → note → wait（署名 王主管）
          台账文件 3 行，字段 at,case_key,action,by,note,target,label
          接口返回 M02 / 王主管 / waiting / log=3
  杀进程 → B 进程启动日志：
          [ledger] 回放出 1 条人工跟进，共 3 条跟进记录
          接口返回 M02 / 王主管 / waiting / log=3  ← 条数、归属、状态、记录数与重启前一致

【实测二：审批单重启后状态明确，不留悬空】
  A 进程：M03（¥1299 超 ¥500 上限）→ 停办，单号 20261022-01
  B 进程：回放出 1 张待审批单（其中 1 张已失效，需重新处置）
          单据带 stale=true + 原因「服务重启时这条处置流程已中断，续办句柄不在了」
          对这张单子点批准 → HTTP 409
            {"ok":false,"stale":true,
             "error":"这条处置流程在服务重启时中断了，当时的续办句柄已不存在，无法在这里批准执行。请重新处置这条案子。",
             "msg_id":"M03"}
  界面上这张卡：chip = 「已失效 · 待重新处置」，**没有批准/驳回按钮**，
  给的是「重新处置这条」+ 一句说明「会按原话完整重跑一遍，金额与依据都会重新算 ——
  不是把这一张单子直接执行掉」。页头口径：1 条待处理（0 条可裁决，1 条已失效待重新处置）。
  → 不摆一个点了必然失败的动作，也不偷偷把断了的流程批掉。

【实测三：重新处置真的重跑】
  点「重新处置这条」（规则通道）→ 回到处置页跑完 → M03 因 ¥1299 再次超限停办，
  队列里出现一张**新的可裁决单** 20261022-03（stale=false）。
  这就是闭环：断掉的单子不假装能续办，但人能一步走到「重新走一遍」。
  术语卫哨 count=0、控制台零报错。

【回放才暴露的一个真 bug：单号跨重启重号】
  单号是「日期-当日序号」，序号在进程内从 1 数起。落了盘之后重启再发一张，
  又变成 -01，与台账里那张重号 —— 回放时「新单被裁决」会连带把旧单一起抹掉，
  症状是「重启后单子凭空消失」，而且日志里一片正常。
  修法：启动回放后 seedApprovalSeq(历史单号) 把当日序号续上。
  验证：B 进程新发的单号是 20261022-02；裁决 -02 之后 -01（失效那张）仍在队列里。

三、前端：渲染分片（脏标记）+ 动作表（desktop/public/index.html）
────────────────────────────────────────────────────────────────────────────────

【渲染分片做了什么】
renderAll() 原来一次重画四块（指标 / 队列 / 正文 / 右栏），副作用全藏在「顺带」里：
保存配置时焦点被冲掉、跟进面板滚到一半被拉回顶部、刚展开的折叠线又合上。
现在拆成五个渲染单元 + 一张脏表：
    metrics / queue / stage / side / chrome
状态改了只标脏（markDirty），末尾 flushRender() 只画变脏的那几块；
window.__renderCount 记每个单元的重画次数 —— 验收用它，不靠眼睛判断「有没有变快」。
renderOnly(...units) 给绝大多数交互用；renderAll() 保留给「整页换掉」的场合
（切视图、启动、换选中案子），它等价于「全部标脏」。

【实测 1：跟进一步操作只动两处】
  贴 M02 → 被复核拦下 → 点「接手跟进」
  __renderCount 前后差：{flush:2, metrics:0, queue:1, stage:0, side:2, chrome:0}
  → 正文（stage）与指标（metrics）**一次都没重画**；side 两次是「处理中 → 结果」。

【实测 2：保存配置不动光标、不重画表单】
  进 #config → 把焦点放进「模型名称」输入框 → 点「保存并生效」
  焦点：before=cfgModel，after=cfgModel（前=后）
  __renderCount 前后差：{flush:1, stage:0, side:1, chrome:1, metrics:0, queue:0}
  → 表单（stage）零重画，只换状态卡 / 密钥提示 / 回执区 / 按钮态（patchCfg()）。
  对比改之前：saveConfig 的 finally 里一句 renderAll() 就把整张表单重画，光标必然丢。

【实测 3：正文滚动位置不丢】
  正文滚到 scrollTop=180 → 点「记一条」
  结果：{before:180, after:180, kept:true, log:6}
  改之前 renderAll() 会把 stage 的 innerHTML 换掉，scrollTop 归 0。

【动作表做了什么】
data-* 内联语义收敛成一张 ACTIONS 表（26 项），click 委托查表、命中即止。
原来那条 ~150 行的 near() if 链现在是：
    for (const [sel, fn] of ACTIONS) { const el = t.closest(sel); if (el) { fn(el); return; } }
**表的顺序就是优先级**：队列条目里的跟进标签嵌在 [data-q] 里面，
必须排在 data-q 之前 —— 上一轮踩过这个坑，现在它是表里两行的先后，不再是「记得写对顺序」。
新增一个可点动作 = 表里加一行 + 元素加一个属性。
