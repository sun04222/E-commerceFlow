一、没跑通的那条不再被删掉（1d69399）
════════════════════════════════════════════════════════════════════

【改动前的问题】runQuery 的失败分支是 st.sessions.filter(x => x.id !== localId)：
一条记录跑挂了，「刚才跑的是什么 / 为什么没成 / 还能不能再试」三件事一起消失，只剩一句 toast。
另外 statusOf(result) 在 result 为 null 时只能返回「处理中」——
一条永远好不了的记录会一直显示在跑。

【改法】失败就地留下：会话加 error 字段（errOf 收成「原因 / 下一步 / 出口类型」），
主区渲染失败卡（原因 + 下一步 + 原样重试），新增会话级状态 sessStatus() 单列「未跑通」一格，
重试用 replaceId 顶掉原记录。

二、MCP 客户端：子进程一死就当场作废（b9a27b4）
════════════════════════════════════════════════════════════════════

【改动前的 7 处隐患】
  1. child 没有 exit / error 处理 → 子进程挂了 mcpState.ready 仍是 true（假在线）
  2. 每次拉数都要挂满 8 秒超时才失败，且没人知道为什么
  3. send 的 setTimeout 没 unref（一个没回音的请求能拖住进程退出）
  4. notify 直接 child.stdin.write，进程已死时抛 EPIPE 没人接
  5. 超时后不 cancel 请求（对方还在算，响应回来无人认领被丢掉）
  6. 工具级失败藏在 isError 里，客户端只认 JSON-RPC error → 报错变成 JSON.parse 语法错
  7. 无重连、无退避、退出时不留子进程处理（每次 Ctrl+C 留一个孤儿 node 占管道）

【正常态】GET /api/connectors 的 mcp 字段：

  ready: true ｜ tools: 9 个 ｜ attempts: 1 ｜ handshakeMs: 267 ｜ timeoutMs: 10000

  POST /api/connectors/pull {"id":"*"}：
  orders-hub    via=mcp added=4
  aftersales-hub via=mcp added=4
  logistics-hub via=mcp added=4
  catalog-hub   via=mcp added=3

  截图：docs/mcp1-channel.png

【杀子进程 + 移走 mcp/server.mjs 之后】—— 两条实测，看的是同一件事：状态立刻作废

  (a) 只杀进程：
      ready   : false
      problem : MCP 子进程被强制结束
      tools   : 0
      （改动前这里会是 ready=true，界面照旧显示「已联通」）

  (b) 杀进程 + 移走文件后拉取：
      via   : file
      note  : MCP 通道未就绪：MCP 子进程退出（退出码 1）：Cannot find module
              '...\mcp\server.mjs'。数据已改从本地文件通路读取。
      added : 0 ｜ updated : 4      ← 按主键 upsert，幂等，不重复堆行
      mcp.ready : false             ← 不能一边报错一边标「已联通」

  截图：docs/mcp2-down.png

【恢复文件后点「重连」】

六、本轮踩到并记下的两个工具坑（不影响产品，但影响验收可信度）
════════════════════════════════════════════════════════════════════

1. agent-browser 的 eval 参数里不能出现 `?`。
   它会把参数当 URL 查询串解析，整个脚本静默失败（退出码 1、无输出）。
   所以所有三元表达式都写成 if/else；或者干脆用 `agent-browser eval --stdin` 走 heredoc。

2. `agent-browser set viewport` 必须在 `open` 之后调。
   先设视口再 open，open 会把视口重置回默认（实测设 900 后 innerWidth 仍是 1264）；
   正确顺序是 open → set viewport → 断言 → 截图，且这些要在同一次 Bash 调用里完成
   （eval 会随机落到 about:blank，这是老问题）。

七、如实说明：本轮没做的事
════════════════════════════════════════════════════════════════════

1. /api/gate 仍然没有界面入口。它是回归门禁，离线模式 8 条约 1 秒，
   但模型模式每条 20–30 秒（8 条要 3 分钟以上），要放进界面得先有「后台任务 + 进度」
   这一层，不是加个按钮的事。本轮不做，理由写在这里，不假装做了。

2. 连接器声明里的 get 类工具（orders_get / refunds_get / logistics_get / sku_get）
   仍然只被 tools/list 列出、没有任何调用点 —— 界面只做整表拉取。
   这不是 bug（拉取只走 list 类工具，参数是空的也没问题），但是一条「声明了却没接上」的缺口。

3. 无障碍（aria-* / focus-visible / 键盘路径）本轮没动，与上一轮同样的理由：
   这一层要么系统性重做，要么零散做几处反而给人「已经支持无障碍」的错觉。
