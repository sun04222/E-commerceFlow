七、Windows 启动器编码 bug（实测发现并修复）
────────────────────────────────────────────────────────────────
现象：系统默认代码页 936（即双击环境）下运行 启动桌面端.cmd，整行被拆碎：
      'mjs' 不是内部或外部命令
      '新服务，端口被占用时会留下一个报错的最小化僵尸窗口。' 不是内部或外部命令
      → 服务起不来，窗口打开是空白

最小用例定位（5 行）：
  A: UTF-8 + 文件内 chcp 65001  → 紧跟在 chcp 之后的那一行被丢掉（MARK1 未执行，MARK2 执行）
  B: GBK  + 不写 chcp           → 所有行完整执行（MARK1 MARK2 都在）
  ⇒ 根因：chcp 写在批处理文件里会让 cmd 的行解析错位；只要文件含非 ASCII 字节，
     代码页对不上时多字节序列还可能吞掉换行、把后续行当独立命令执行

修复：
  1. 启动桌面端.cmd 改为纯 ASCII（非 ASCII 行数 = 0），说明文字用英文，注释写明原因防回改
  2. 行尾统一 CRLF（79/79）
  3. 等待端口由 timeout /t 1 改为 ping -n 2 127.0.0.1（timeout 在 Git Bash/MSYS 会被 GNU timeout 顶掉）

修复后实测（同一代码页 936）：
  启动器输出: Starting local service: http://127.0.0.1:8787 ...   ← 干净，无拆行
  端口      : TCP 127.0.0.1:8787 LISTENING
  服务响应  : HTTP 200
  窗口      : Edge --app 进程与 8787 建立 ESTABLISHED 连接（窗口已加载页面）

八、结论
────────────────────────────────────────────────────────────────
1. 对话式自主执行闭环成立：贴一句客户原话 → 六步执行流 → 结构化结果卡，默认无需任何确认。
2. 人工审批是真环节而非装饰：停办 → 审批卡（四问）→ 批准则真实执行并结单 / 驳回则如实收口，两条路都经过实测（前端 + 服务端各一遍）。
3. 自主边界可调：顶层开关关闭后，原自动档案件全部转入审批。
4. 指标条、队列徽章、六步四态与真实结果一致，无一处是预写台词。
5. **监管指标条是入口不是装饰**：五档全部可点、可筛、可直接进入操作（审批中心 / 可复制回复）。
6. 工程词汇零泄漏（多视图 × 50 禁止词）；引擎侧门禁 8/8 无回归。
7. Windows 一键启动器在本机默认代码页下可正常工作（修复前不可）。
