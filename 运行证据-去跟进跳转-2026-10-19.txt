────────────────────────────────────────────────────────────────────────────────
一、改之前是什么样（先把病因说清，否则改了也不知道改对了没）
────────────────────────────────────────────────────────────────────────────────

原实现（两处，两套语义）：

  data-goto-fu="1"  →  if (near("[data-goto-fu]")) { $("fuPanel").scrollIntoView(...) }
  data-open-fu="1"  →  找「第一条待接手」→ st.cur = 它 → 滚 fuPanel

问题不在「没绑事件」，在于绑的那个动作不成立：`#fuPanel` 只在
「选中一条 + 这条需要人工跟进」时才渲染，而且住在右栏里。于是三种情形必然空转：

  情形                        面板在不在                     结果
  ─────────────────────────  ─────────────────────────────  ──────────────────────
  在数据源页 / 审批页          不在（右栏换了内容）            静默无反应
  没选中任何案子               不在（右栏是概览）              静默无反应
  窄屏 ≤1180px                在，但右栏 display:none         对着隐藏元素滚动 = 无反应

更深一层：同一个词「去跟进」有两个属性、两套语义（滚一下 / 跳第一条）。
入口一多，总有一个会漏掉「窄屏右栏是抽屉」这一层 —— 漏的恰好是第一眼会点的那个。

────────────────────────────────────────────────────────────────────────────────
二、改成了什么
────────────────────────────────────────────────────────────────────────────────

1. gotoFollowUp(ref, opts) —— 全站唯一跳转入口。四个入口只准调它：
   结果卡横幅 / 回复区「需人工跟进」/ 队列跟进标签 / 右栏概览「接着跟进」。
2. ref 带「这条案子自己的标识」（fuKey = msgId）。不带标识才退化为「第一条待接手」，
   且只有右栏概览那个泛入口会这么调。
3. revealFollowUp() —— 送进眼里：宽屏滚右栏；窄屏先 toggleDrawer("side") 唤出抽屉，
   等 80ms（0.2s 入场动画）再滚，否则滚的是还没布局的元素。
4. 极薄哈希路由：
     #fu/<案件主键>   #approvals   #sources
   状态 → 地址：renderAll() 末尾 syncRoute()，用 history.replaceState（不污染浏览历史）
   地址 → 状态：boot() 末尾 + hashchange → applyRoute()（silent，找不到也不弹提示）
5. 队列跟进标签 <span> → <button type="button" data-goto-fu="<key>">，
   并在事件分派里排在 data-q 之前（标签嵌在条目里，先判 data-q 只会选中条目、跳不进去）。
6. 旧的两段逻辑（data-goto-fu 只滚动 / data-open-fu 自己找第一条）已删除。

三、阶段一：宽屏 + 两条不同案子 —— 「点哪条去哪条」
────────────────────────────────────────────────────────────────────────────────

引擎切到「内置规则判定」（避免每条等 20–30 秒）。

跑 M02（未收到货·物流已签收）：
  {"verdict":"已拦截，未执行任何处置","fuBtn":"M02"}
跑 M07（退款金额超实付）：
  {"verdict":"已拦截，未执行任何处置","fuBtn":"M07"}

从 M07 点「去跟进」：
  {"clickedKey":"M07","hash":"#fu/M07","activeRow":"M07","match":true}
  {"fuPanel":true,"sideTab":"处置详情","panelTop":142,"inView":true}

回到 M02 点它自己的「去跟进」：
  {"clickedKey":"M02","hash":"#fu/M02","activeRow":"M02","match":true}

→ 成对证据：两条案子各落各的，不串。判据是 clickedKey === activeRow === hash 尾段。

四、阶段二：窄屏抽屉 / 跨视图入口 / 重开页面
────────────────────────────────────────────────────────────────────────────────

【窄屏 1100】先看断点是否真的把右栏收起来了：
  {"sideDisplay":"none","navDrawer":"grid"}          ← 右栏确实 display:none

点「去跟进」：
  "clicked:M07"
  {"sideOpen":true,"maskOn":true,"hash":"#fu/M07","fuPanel":true,"panelInView":true}
  → 按钮自己把右栏抽屉唤了出来，并且面板真的在视野内。这是原实现最像「坏了」的场景。

【宽屏 1440 · 从数据源页进入】先确认此刻面板确实不存在：
  "to sources"
  {"view_sources":true,"hash":"#sources","fuPanel":false}     ← fuPanel=false，原实现到此必空转

点队列里的跟进标签：
  {"clickedTag":"M07","hash":"#fu/M07","activeRow":"M07","fuPanel":true}
  → 跨视图入口可用，且落到标签所属的那一条。

【重开页面 / 粘链接】先真的接一次手，让台账里留下记录：
  {"owner":"跟进人 王主管","hash":"#fu/M07"}

再打开 http://127.0.0.1:8787/#fu/M07 ：
  {"hash":"#fu/M07","queue":2,"activeRow":"M07","fuPanel":true,"panelInView":true}
  → 服务端按台账回灌了案子，地址把它落到同一条。
  （说明：只有当这条案子在台账里存在、或被入站流水回灌时，重开才能接续；
    单文件版没有服务端可回灌，刷新即重置 —— 与既有口径一致，不是本轮引入的。）

【另外两个直达地址】
  http://127.0.0.1:8787/#sources   → {"hash":"#sources","sideTab":"数据源状态"}
  http://127.0.0.1:8787/#approvals → {"hash":"#approvals","navApprActive":true}

八、这次没做的
────────────────────────────────────────────────────────────────────────────────

1. 测试脚本里踩过两次选择器坑，如实记下（不是产品缺陷，是探针写错）：
   · 队列条目是 [data-q]，但「示例」条目是 [data-preset]，第一次探针用 [data-q] 数到 0；
   · 状态判据不要用 /仅退款|已处理|待人工审批/ 这种宽泛正则取首个匹配 ——
     会命中顶栏指标标签。要以确定元素（.result .banner b）或截图为准。
2. 普通会话（不需要跟进的）不进哈希 —— 它本来要先跑一遍才有结果，没法凭空指过去。
3. 无障碍仍未做（见 docs/04 第九节第 5 条），本轮未动。
