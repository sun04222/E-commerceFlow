================================================================================
一、这一页要解决什么
================================================================================
模型通道是本工程唯一的外部依赖，原先只写在项目根 .env 里。改一次密钥要：
找到文件 → 打开 → 改 → 记得重启（src/env.ts 有模块级缓存）。前两步对会开终端的人
不算事，但这不是售后运营该付的代价 —— 所以把四条配置搬进界面。

界面入口：左侧图标轨最下面那个滑杆图标（#navCfg），地址 http://127.0.0.1:8787/#config

================================================================================
二、接口面（服务端三条路由）
================================================================================
GET  /api/config      → 回显当前配置（密钥只给末 4 位）
POST /api/config      → { baseUrl, model, timeout, apiKey?, clear_key? }
POST /api/config/test → 真跑一次极短补全，回 { latency_ms, model, reply }

$ curl -s http://127.0.0.1:8787/api/config
{"ok":true,"editable":true,
 "baseUrl":"https://open.bigmodel.cn/api/paas/v4","model":"glm-4-flash","timeout":60,
 "key_set":true,"key_mask":"****ka0a","usable":true,"problem":"","shadowed":[],
 "env_file":".env（项目根目录）"}

注意 key_mask：只有末 4 位。完整密钥不出现在响应里，也不出现在界面上。

================================================================================
四、保存：改完即生效（不重启）
================================================================================
操作：把「单次超时」改成 45 → 点「保存并生效」

$ diff .env 备份 .env
7c7
< LLM_TIMEOUT=60
---
> LLM_TIMEOUT=45

$ curl -s http://127.0.0.1:8787/api/config
{"ok":true,"editable":true,... "timeout":45, "key_set":true,"key_mask":"****ka0a",...}

- 文件里只有 LLM_TIMEOUT 这一行变了：密钥行、注释、其余内容一字未动（写回按行替换）
- 接口立即返回 45：进程内缓存已重载（src/env.ts 的 resetEnvCache），不用重启
- 页面重渲染后 timeout=45，密钥框仍只显示 ****ka0a

对照（如果没有 resetEnvCache）：文件改了、进程还是旧值 —— 界面显示「保存成功」，
下一次判定却仍按 60 秒超时跑。这类「保存成功但不生效」是最难查的一类。

================================================================================
五、测试连通：真调用，失败不假装
================================================================================
【成功】点「测试连通」

{"chip":"连通已验证","k":"已就绪。",
 "out":"连通正常 · 用时 893 ms\n模型：glm-4-flash\n返回：OK"}

（另一次测得 1041 ms，同一口径）

截图：docs/cfg2-verified.png

【失败】把密钥换成一个格式完整但无效的值，保存后再点「测试连通」

{"chip":"模型通道已填齐",          ← 填齐 ≠ 可用：这一档只表示四项齐全
 "keyPh":"****0000",              ← 仍然只显示末 4 位
 "out":"没有连上 · 用时 244 ms\n模型服务返回 401：令牌已过期或验证不正确\n\n
        常见原因：地址或模型名不对、密钥无效或已过期、本机访问不到这个地址。"}

- 错误原文来自服务商，原样显示；我们只做一件事：把错误消息里可能夹带的完整密钥
  替换成 ***（server.mjs 的 /api/config/test 分支）
- 角标不会因为「填齐了」就跳成可用；只有真验过才转「连通已验证」
- 改过配置、或重新进页面，之前的验证结论作废（cfgTested 归 false）

测完已把 .env 还原为改动前的原值，并重启服务确认 timeout 回到 60。

六、单文件版的诚实降级
================================================================================
$ agent-browser open "file:///.../demo.html#config"

{"hash":"#config","chip":"此形态不可配置",
 "k":"当前形态不能在这里改。",
 "body":"单文件版只有一个离线规则引擎，没有可以写回配置的服务端进程。",
 "deadForm":false,                 ← 不渲染填了也存不下去的输入框
 "hasCmd":true}                    ← 给出本地服务模式的启动命令

截图：docs/cfg4-demo.png

理由：单文件版双击即用、零安装，代价是它没有进程可写回配置。摆一组填了也存不下去
的表单，比直接说「这一页要用本地服务模式」更浪费人的时间。

八、路由回归（这一页牵连到的旧路径）
================================================================================
直接打开        → 落点
#sources        → h1=数据源
#config         → h1=接口设置
#fu/M07（先跑过 M07）→ hash=#fu/M07 / fuPanel=true
点「去跟进」    → {"hash":"#fu/M07","fuPanel":true}
地址清空        → 回默认视图（navChat=active，navCfg 去掉 active）
#fu/NOTEXIST    → 地址被当前状态覆盖（不留一个指向不存在位置的地址）

说明：带 #fu/<key> 重开能接续，前提是这条案子在台账里存在或被入站流水回灌（服务端版）。
预设条跑出来的会话没有落到台账，刷新后自然回不来 —— 这是既有口径，不是本轮引入的限制。
